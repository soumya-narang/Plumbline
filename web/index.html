Which services exist, and which face the internet, is declared, not discovered. Verdicts come from deterministic code, never from a model.

Three habits that keep an answer honest

Show the path, not a score

Every exposed service comes with the exact chain from its own dependency down to the poisoned version, found with a shortest-path query, and a receipt you can re-derive.

Say what you assumed

Clearing a service rests on facts: the lockfile hasn't changed, this version isn't on the advisory. Plumbline stores each fact next to the decision that leans on it.

1. The lockfile has not changed

keyv@6.0.1 is not on the advisory

No longer true since 12:45

Reopen only what broke

When a fact stops being true, one query finds the decisions that leaned on it. Everything else stays decided, so nothing is re-reviewed by habit.

One graph does three jobs

Evidence, memory and the agent's tools all run on a single FalkorDB graph. Here is what each job asks of it.

Evidence
A shortest-path query over the resolved dependency edges returns the chain for every exposed service.
Memory
Decisions point at the facts they assume. One traversal finds exactly which decisions a new event breaks.
Tools
An MCP server exposes read-only tools, including a fleet-wide fix-first query and PageRank over each dependency graph, plus a shared work queue for hand-offs between agents. The agent reaches the graph only through them.
